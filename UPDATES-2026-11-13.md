## 3. Changes by theme

### 3.1 Detection fixes and new permission types (`008aba7`)
These are applied **at scan time**, so a scan must be re-run to get them.

- **GenericWrite was being missed.** `src/BH.Native.cs`: an ACE granting write-to-all-properties (WriteProperty, no object type) now emits `GenericWrite`. Before, it required the full expanded write mask, so a plain all-properties WriteProperty grant produced no edge.
- **Constrained delegation targets now resolve by SPN host.**
  - `src/BH.Native.cs`: new `DirectoryIdentity.SpnHost(spn)` returns the host part (`cifs/fs01.corp.local:445` becomes `fs01.corp.local`).
  - `src/BH.Collection.Native.cs`: `AllowedToDelegate` edges now target `SPNHOST:<HOST>` instead of the full SPN string.
  - `src/BH.Index.Native.cs`: when loading objects it also writes alias rows `SPNHOST:<host>` for each registered SPN host and for each computer's own DNS name, so those targets resolve to the account that owns the host. (The older `SPN:<full SPN>` alias is kept for compatibility.) This part applies when the index is built, so a re-report is enough.
- **Default noise removed.** `src/BH.Collection.Native.cs`: ACL trustees Local System (`S-1-5-18`) and Enterprise Domain Controllers (`S-1-5-9`) are now skipped, in addition to Creator Owner (`S-1-3-0`), Creator Group (`S-1-3-1`) and Self (`S-1-5-10`).
- **New edge types derived from the security descriptor** (`src/BH.Native.cs`, new constants for the Self and ReadProperty rights and four attribute GUIDs):

| Edge | Right and attribute | Applies to |
|---|---|---|
| `AddSelf` | validated write (0x08) on `member` (`bf9679c0-...`) | groups |
| `AddKeyCredentialLink` | WriteProperty on `msDS-KeyCredentialLink` (`5b47d60f-6090-40b2-9f37-2a4de88f3063`) | users, computers |
| `WriteSPN` | WriteProperty on `servicePrincipalName` (`f3a64788-5306-11d1-a9c5-0000f80367c1`) | users, computers |
| `ReadGMSAPassword` | ReadProperty on `msDS-ManagedPassword` (`e362ed86-b728-0842-b27d-2dea7a9df218`) | users, computers |
| `WriteGPLink` | WriteProperty on `gPLink` (`f30e3bbe-9ff0-11d1-b603-0000f80367c1`) | OUs, domain, sites |

  The report glossary, traversal and scoring already knew these edge types.
- `ReadLAPSPassword` is **not** derived natively. LAPS attributes use a per-forest schema GUID the collector does not resolve. It is only available through SharpHound import. This is documented in `README.md`.
- `tests/Smoke.ps1`: added assertions for each new mapping and for the GenericWrite fix.

### 3.2 Trace tool (`91764c0`)
New `Trace-ObjectAcl.ps1`. For one object it prints the raw ACEs in the live DACL (read from the DC with the same controls the collector uses), the edges the collector's parser derives, and, with `-IndexPath`, the ACL edges stored in `graph.sqlite` with a `TrusteeInLiveDacl` column. Has an offline mode (`-DescriptorHex`). Purpose: show whether a displayed permission really exists in the live ACL.

### 3.3 Names for trustees in other domains (`3a5387f`)
Cause of the "SID shown instead of a name" problem: name lookup only searched the scanned domain.

- `src/BH.Core.psm1`
  - `Resolve-BHExternalPrincipals` now does two passes: the scanned domain, then the **forest Global Catalog** (port 3268, empty search base) for SIDs still unresolved. Names found there are labelled `Name@domain`. If the Global Catalog is unreachable it logs a warning and carries on. `foreignSecurityPrincipal` stand-in objects in the local domain are ignored.
  - `New-BHLdapConnectionBounded` takes a new `-Port` parameter (default 389).
  - New private helpers `Get-BHDnDomain` and `ConvertTo-BHSidFilter`.
- `BH.Gui.ps1`
  - GUI scans now pass `-ResolveExternalNames` (it was never enabled in the GUI). This can add up to about 5 minutes per scan target.
  - New command-line action: `.\BH.Gui.ps1 -ResolveNames -ScanPaths <scan folder> -Server <dc>` names the holders of an **existing** scan without rescanning. Re-run the report afterwards.
- Trusted domains outside the forest are not searched and stay as SIDs.

### 3.4 Missing index error and path handling (`890d8d6`)
SQLite reports a missing file as "SQLite error 14: unable to open database file", and relative paths resolve from the process folder, not PowerShell's current folder.

- `src/BH.Index.Native.cs`: `GraphIndex` now throws `Graph index not found: <full path>` with a hint when a non-created index file does not exist.
- `Trace-ObjectAcl.ps1`: validates and resolves `-IndexPath` before any LDAP work.
- `src/BH.PathExplorer.ps1`: the findings button passes the resolved full path.

### 3.5 Progress, timing and scan bar (`d18854b`)
Merge and report used to show one static label for an hour or more, and the scan bar jumped to 100% on the first update.

- **Native progress hook** (`src/BH.Index.Native.cs`)
  - `GraphIndex.Progress` (`Action<string,long,long,long>`: label, done, total, records).
  - `Import` reports per file (label includes the scan folder and file, "file i of n"), every 65,536 records, and before the final commit ("Saving the loaded data to disk ... no further updates until it finishes"). `done`/`total` are bytes of input.
  - `WriteMerged` reports each object type and relationship type ("step i of 23"). `done`/`total` are steps.
- `src/BH.Core.psm1`
  - New `Set-BHIndexProgress` (throttled to one update per 2 seconds; a step change always passes). `Import-BHGraphDataset` accepts `-OnProgress`.
  - `Start-BHMerge` has three named steps: "Step 1 of 3: Loading into a working index", "Step 2 of 3: Counting (reads the whole working index)", "Step 3 of 3: Writing merged files (one full pass per type, can be slow)". Callback shape: `'phase' label count` and `'detail' label records done total`.
  - `Start-BHCollection` also passes `shardsDone`, `shardsTotal` and a stage text to its progress callback, with separate stages for directory collection, endpoint collection and external-name lookup.
- `src/BH.Report.psm1`: loading detail goes to the callback as a transient line (second argument is an object with `Pct`). New step labels: "Counting objects and relationships (reads the whole index)", "Collecting relationship evidence and group summaries", "Ranking permission holders (scans every permission relationship)", "Preparing the saved analysis snapshot (Deep mode)", "Building the HTML report and publishing the files".
- `BH.Gui.ps1`
  - New helpers: `Format-BHSpan`, `Format-BHBytes`, `Set-BHBar`, `Start-BHOperation`, `Set-BHOperationProgress`, `Get-BHOperationText`, `Complete-BHOperation`.
  - Merge and report status is two lines: step and detail, then time in step, total time, time since last update, and disk activity (bytes written and time of last disk write, counting only files written since the run began). Logs get timestamps and per-step durations.
  - Scan bar: completed targets plus the finished share of the current target's containers. Status line shows containers finished, objects, edges, errors, objects per second, time on this target and a rough time remaining.
  - **Behavior change:** with "Automatic report" ticked, a multi-OU scan used to merge all scans first and report on the merged copy. It now builds **one report directly from the scan folders** (the report de-duplicates across inputs). The Merge tab is unchanged.
  - Command-line scan, merge and report callbacks show the same detail.
- `src/BH.Gui.Layout.ps1`: status row made taller (46 px) for the two-line status.
- `README.md`: documents the above.

## 4. Behavior changes to be aware of

- New scans produce more `GenericWrite` edges (any all-properties write grant), fewer default-trustee edges (SYSTEM and Enterprise Domain Controllers), and five new edge types.
- Constrained-delegation edges now point at `SPNHOST:` targets.
- GUI scans spend extra time looking up names (bounded to 5 minutes).
- Auto-report after a multi-OU scan no longer produces a merged dataset.
- `BH.Core.psm1` and `BH.Gui.ps1` had mixed line endings; they are now LF only (no functional effect in PowerShell).

## 7. Known limits and not-yet-done

- `ReadLAPSPassword` is not derived natively.
- Standalone `BHTest.Viewer.ps1` not rebuilt (see section 1).
- Collector does not collect `foreignSecurityPrincipal` objects, so forest users who are members of local groups do not appear as members. (The collector's LDAP filter excludes that object class.)
- Report analysis only reports findings reachable from well-known privileged groups and the domain object. A scan of an OU that does not include them shows 0 candidates.
- Other issues found in review and not fixed: subtrees under some container types are skipped; deny-ACE precedence over-suppresses; one object error fails the whole scan; a runspace is left undisposed per LDAP connection; endpoint collection waits on dead hosts.
- Proposed but **not implemented**: counting during the load (removes the long silent counting passes after loading), cheaper object loading (fewer SPN aliases, parallel compression, optional light mode), and incremental reports for repeated scans.
